# V6.20 Storage Boundary Hardening

## Architecture change

V6.20 completes the remaining direct persistence cleanup in `src/main.js`.

All quotation startup reads, legacy profile migration writes, logo migration/storage, and preset reads now flow through the shared Storage Repository instead of calling `localStorage.getItem/setItem/removeItem` directly.

## Data safety

- Legacy company-profile migration uses verified repository writes.
- Legacy logo extraction captures both affected keys before mutation.
- A failed logo migration write rolls back the captured snapshot.
- A failed quotation-state write during logo migration rolls back the snapshot.
- Repository `remove()` verifies that the key is actually gone before reporting success.
- Existing storage keys remain unchanged.
- No destructive schema migration is introduced.

## Regression protection

The smoke gate now rejects direct `localStorage.getItem/setItem/removeItem` calls in `src/main.js` (except construction of the repository adapter itself).

Repository tests cover failed removal verification.

## Compatibility

This is an incremental Strangler Refactor. Backup schema v4, persistent business keys, existing quotation history, presets, customer library, product catalog and logo data remain backward compatible.
