# V6.28 Search, Feedback and Drawer Contracts

## Constitution rules applied

- Reuse existing components before creating new ones.
- Do not introduce a parallel design system.
- Preserve one semantic status language.
- Keep application UI isolated from report/print styling.
- Incremental migration only.

## Search

A shared Search contract now owns background, border, radius, icon, placeholder and hover semantics. Existing search implementations are migrated in place.

## Toast

Toast remains short-lived feedback. Runtime now exposes a whitelisted semantic tone through `data-tone`:

- neutral
- info
- success
- warning
- danger

Existing calls without a tone stay neutral.

This version does not convert important persistent errors into toast; those flows remain candidates for later Error UX cleanup.

## Drawer

The existing Preview Customizer already behaves as a real drawer. It now consumes shared Drawer surface/border/radius/elevation tokens instead of creating a second drawer implementation.

## Safety

- No business data changes.
- No storage schema changes.
- No report theme changes.
- No print/PDF changes.
- No new navigation destination.
